# レビュー修正と性能検証（2026-09-10）

レビューで再現した4件を修正した。性能測定では、最近の変更によりpaddingと曖昧塩基を含むORF探索が約18～20倍に遅くなるケースが見つかったため、判定を変えずに検索と集計を改善した。GFF付きギャップ整形には新しい保護・検証処理のコストが残る。測定した既存処理では大幅な最大RAM増加は認めなかったが、新規PLM教師の全量学習やGPU使用量まで保証する結果ではない。

## 修正

1. **凍結評価の判定保留**：CNN・PLM・centroidの予測を同じ利用可否の契約にそろえた。確率指標と層別reliabilityは計算済み行に限定し、被覆率、判定保留数、受理行だけの判定指標を出力する。NPZにも利用可否・判定理由を保存する。全行が未計算ならBrier/APはnullになる。
2. **学習と推論のクラス不一致**：CV内部の部分クラス学習は維持し、最終モデルは推論CLIが要求する5クラスを検証する。不足する場合はモデル・学習レポートを書き換える前に具体的な不足クラスを示して停止する。
3. **CNNのバッチ依存性**：window間集約から、バッチ長をそろえるための空windowを常に除外する。`mask_padding=False`でも他の配列の長さによって予測や当該行の勾配が変化しない。再現例のスコアは単独／混合とも0.5となった。
4. **凍結評価の途中失敗**：すべてのNPZとmetricsを一括でステージし、I/Oエラー・KeyboardInterrupt・確定途中のエラーではロールバックする。完了済みの評価は引き続き上書きしない。SIGKILLなど捕捉不能な終了の完全復旧は今回の保証範囲ではなく、残ったロックは所有者確認が必要。

## 性能改善の内容

- 以前は、配列に1文字でもNなどがあると、paddingとORF探索は全コドンをPythonで展開していた。末端に人工的に補ったNでもこの経路に入り、長さに比例した大量のPython呼び出しが発生した。
- 遺伝暗号ごとに、全展開が確定stopになるIUPAC三つ組だけを列挙・キャッシュし、文字列検索で位置を得る。TARなどの確定stopを維持し、通常のTANや特殊コードのsense/stop兼用コドンを誤って除去しない。
- コドン集計は種類ごとの頻度を先に数え、同じ三つ組の属性判定を繰り返さない。stopの位置リストや配列全体を大文字化した追加バッファも不要になった。末端例外・欠損・曖昧性の集計規則は維持した。
- paddingのレポートなし経路は、既に調べた末端補完候補のstop数を再利用する。

## 比較方法

| 名称 | ソース |
|---|---|
| 大幅変更前 | `212a120`：9月8日の一連の変更が始まる直前の履歴。版表示0.28.3 |
| 修正直前 | `dc1aab6`と、レビュー開始時から存在した未コミット変更のスナップショット |

比較用コードは別ディレクトリへ展開し、現在のブランチを切り替えずに実行した。Python 3.12.14、Apple M2 Max／arm64／macOS、NumPy 2.5.2・Biopython 1.88を共通に使用した。PyTorch・BLAS等のCPUスレッドは1に固定し、ワークロード×ソースごとに新しいプロセスを起動した。入力作成、モデルロード、出力比較は時間測定から除き、1回ウォームアップ後の反復中央値を使う。最大RSSは入力・ライブラリ・ウォームアップ・検証も含むプロセス全体の最大値で、差分割当量ではない。

主にコア処理は7回、CNNは3回反復し、別の測定パスでも確認した。ソース実行順はケースごとに反転した。マシンは専有されておらず、特に短時間処理は負荷による変動がある。数msの処理や学習結果が一致しないケースを、速度改善の根拠にしない。

出力はタイミング外でSHA-256を比較した。filterは新規診断列を除く共通列、paddingは配列・stop判定・補完有無、CNN推論は確率と判定の全配列を比較する。ORFは選択結果の全フィールド、backtrimとgapjustは出力ファイル全体を比較する。PTS2定義が変わった既定特徴量と、学習結果が一致しない旧CNN学習は、同等出力の性能比較から除外した。旧モデル用特徴量はlegacyスキーマでも別途比較した。

## 測定結果

同じ出力を確認したケースの中央値。RAMは大幅変更前→修正後の最大RSS（MiB）。

| 処理 | 大幅変更前 秒 | 修正直前 秒 | 修正後 秒 | 最大RSS MiB |
|---|---:|---:|---:|---:|
| 翻訳（300万nt）* | 0.0062 | 0.0141 | 0.0108 | 80.2 → 82.0 |
| filter（1,000×1,500nt） | 0.1441 | 0.2643 | 0.1276 | 48.6 → 48.5 |
| filter（1×3,000万nt） | 4.3967 | 8.0793 | 1.8956 | 102.8 → 102.7 |
| padding（1,000×1,499nt） | 0.1019 | 1.8519 | 0.1260 | 47.5 → 48.5 |
| ORF（300×3,000nt、ACGT） | 0.1472 | 0.2204 | 0.1305 | 46.8 → 48.1 |
| ORF（300×3,000nt、ACGTN） | 0.0880 | 1.4258 | 0.0734 | 46.8 → 46.8 |
| backtrim（200配列×3,000codon） | 0.0771 | 0.1178 | 0.0903 | 64.5 → 68.3 |
| gapjust＋GFF（1,000万nt、1万feature） | 0.3579 | 0.6082 | 0.6778 | 127.2 → 135.7 |
| 旧モデル用特徴量（1,000×500aa） | 1.0642 | 1.1607 | 0.9680 | 67.2 → 68.3 |
| 既存CNN推論（512配列） | 19.0217 | 18.9862 | 19.1068 | 242.9 → 239.6 |

* 翻訳は別パスでは大幅変更前0.0062秒／修正直前0.0060秒だった。今回の0.0062→0.0108秒だけで75%の回帰と断定できない。絶対時間が短く、負荷による変動に対して明確な結論を出せなかった。

- **paddingと曖昧ORF**：約18～20倍の遅延を解消した。今回の修正で修正直前からそれぞれ約93%・95%短縮し、出力を維持した。コドン集計も改善した。
- **残るコスト**：GFF付きgapjustは大幅変更前の約1.7～1.9倍。CDS保護・Parent/phase診断・編集範囲と入出力座標の検証が追加されたためで、これらの検証を省略する変更はしていない。今回の修正でこの経路の実装は変更していない。
- **RAM**：最終パスの同等出力ケースでは増加は最大約7%、別パスのGFFでも約11%で、倍増のような増加は観測しなかった。単一3,000万塩基でも約103MiBを維持した。
- **CNN**：同じチェックポイントの推論は約19秒／240MiBで同等だった。CNN学習は最終パスで大幅変更前4.04秒・396.6MiB、修正直前3.24秒・328.1MiB、修正後2.74秒・330.1MiBだったが、旧実装との学習結果のハッシュが一致しないため速度改善とは扱わない。修正直前と修正後の学習結果は一致した。
- **特徴量**：既定PTS2定義は意図的に変わったため旧出力と一致しない。旧モデル用legacy定義では全特徴量が一致し、大幅な時間・RAM増加は観測しなかった。
